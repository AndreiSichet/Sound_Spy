# Decision log

| Date | Decision | Reason |
|---|---|---|
| 2026-11-13 | Record-then-process first; real-time streaming later. | Simpler to develop, debug and evaluate offline. (Refined 2026-11-14: one chunk-based engine serves both.) |
| 2026-11-13 | Laptop built-in mic for the Semantic tab; ReSpeaker XVF3800 4-mic USB array from module 3 onward. | Sound-type extraction needs no array; localization and beamforming do. Device profiles make the switch a config change. |
| 2026-11-13 | Fine-tune a pretrained audio model instead of training from scratch. | Limited labelled data and compute; pretrained audio representations transfer well. |
| 2026-11-13 | Extraction: classical detector-guided spectral masking baseline first, neural extraction later. | A transparent baseline gives reference metrics before adding neural complexity. |
| 2026-11-13 | Python + PyTorch; Windows 11 + NVIDIA GPU. | Available hardware and the de-facto ecosystem for audio deep learning. |
| 2026-11-14 | Product renamed **Sound Spy**; package and CLI `soundfocus` → `soundspy`; monorepo with `backend/` and `frontend/`. | The app becomes a desktop-local web app with three tabs (Semantic, Spatial, Sources). |
| 2026-11-14 | **The backend owns all audio I/O.** The browser never captures the mic and does not play live audio; it only plays saved files (A/B comparison). | Browsers apply echo cancellation / noise suppression / AGC and handle multichannel arrays poorly; live output goes straight to the laptop's output device. |
| 2026-11-14 | **One streaming engine for offline and live.** Every stage is a stateful, chunk-based `Processor` / `SideProcessor`; offline = feeding a file chunk by chunk. | Real-time later needs no redesign; one code path to test. |
| 2026-11-14 | **One `TargetSpec` for all three tabs** (`labels`, `direction`, `source_id`, `attenuation_db`). | Processors read only the fields they need; tabs differ only in what they set. |
| 2026-11-14 | **The Python library is the core; the API is a thin layer.** `api/` imports the library, never the reverse; the CLI stays for development, data and training jobs. | Library stays testable and usable without a server. Enforced by a test. |
| 2026-11-14 | **FastAPI** for REST + WebSocket, served by uvicorn. | Async WebSocket support, Pydantic schemas, automatic OpenAPI docs. |
| 2026-11-14 | **SQLite via SQLAlchemy 2.x** for recordings and processing runs; audio stays on disk. No migrations tool yet — **add Alembic when the schema starts changing.** | Zero-setup local database; switching to PostgreSQL later = changing the URL. |
| 2026-11-14 | **No Docker for now**; native dev with `uvicorn` + `npm run dev`. | Microphone and GPU access from containers on Windows is impractical. |
| 2026-11-14 | **Frontend:** React + TypeScript (strict) + Vite + Tailwind CSS + Zustand; Canvas for live waveform/spectrogram/meters, D3 for the polar source map, Recharts for metric charts. | Mainstream, fast tooling; Canvas handles high-rate live data better than SVG/DOM. |
| 2026-11-14 | **Classes defined in `configs/classes.yaml` and mapped to the AudioSet ontology** (SemanticHearing style), foreground = selectable classes, background = everything else. | Lets datasets with different label vocabularies (ESC-50, FSD50K, own recordings) feed one label set. |
| 2026-11-14 | **Extraction has two implementations behind one `Extractor` interface:** detector-guided masking baseline and a label-conditioned neural TSE model (Waveformer-style). | Baseline for comparison; neural model for quality. Ideas from SemanticHearing (MIT); no code copied so far. |
| 2026-11-14 | Frontend uses **TypeScript 6.0**, not 7.0. | typescript-eslint 8.x supports TypeScript < 6.1; TypeScript 7 (native port) is not supported yet. |
| 2026-11-14 | Backend on **`127.0.0.1:8765`** (was 8000); the Vite dev proxy targets `http://127.0.0.1:8765`, not `localhost`. | On the dev machine Docker Desktop and WSL already listen on port 8000 (`localhost` → `::1:8000` hits the WSL relay). An unused port + explicit IPv4 avoids both. |
| 2026-11-14 | Each class has an internal ID (the YAML key), a `display_name`, a `description` and `audioset` names; the API sends only ID, display name and description. | AudioSet names are for mapping datasets, not for users. The UI text can be renamed without touching trained models or the database. |
| 2026-11-14 | Step reports are given in chat, not written to files; `CLAUDE.md` keeps the rules, a short current-state snapshot (overwritten) and a 2–3 line step log; `project_insights.md` explains how the app works and is updated every step. | Claude Code reads `CLAUDE.md` in full every session; a long changelog would bury the rules. The explanation for humans lives in one place. |
| 2026-11-14 | Adapted third-party code is recorded in the "Third-party code" section of `project_insights.md` (and keeps its license header), not in a separate notices file. | One document for everything a reader needs to know; nothing has been adapted so far. |
| 2026-11-14 | Without an explicit `hostapi`, a device resolves to its twin on the most preferred host API: WASAPI → DirectSound → MME → WDM-KS; twins match on the first 31 characters of the name. WASAPI streams use `auto_convert=True`. | PortAudio's default device is the MME one, which resamples to 44.1 kHz and truncates names; WASAPI gives the native rate (48 kHz here) with lower latency. |
| 2026-11-14 | `MicSource.chunks()` uses a bounded queue that drops the **oldest** chunk when full, and counts the drops. | For live listening fresh audio matters more than complete audio; a hidden backlog would add ever-growing latency. |
| 2026-11-14 | After opening a microphone, leading **exact-zero** frames are discarded (at most 1 s). | Measured: a new WASAPI stream on the dev laptop starts with exactly 500 ms of digital zeros. A real mic never outputs exact zeros; the 1 s cap keeps a truly muted mic visible. (Retest: the zeros came from the Windows enhancement processing and vanish with it off; kept as a safety net.) |
| 2026-11-14 | `check-mic`'s "digital silence" counts only runs of exact zeros lasting ≥ 5 ms. | Measured on the honest laptop mic: a 16-bit converter outputs isolated exact zeros (~1.5 % of samples, runs ≤ 0.1 ms, as often as the codes ±1). Counting every zero made the warning fire on healthy input. |
| 2026-11-14 | A recording's JSON sidecar is the source of truth; the database is an index rebuilt from the sidecars (on API startup and on `GET /api/recordings`). The CLI writes files only. | Keeps the library free of SQLAlchemy, lets recordings be copied/moved as plain files, and means the database can always be rebuilt from `data/raw/`. |
| 2026-11-14 | An index row whose WAV file disappeared is **deleted** (not flagged with a `missing_since` column). | No schema change and no migrations tool needed yet; the next sync re-adds a file that comes back. Revisit when processing runs exist (step 06): deleting a recording row also deletes its runs. |
| 2026-11-14 | Recording times are stored in UTC in SQLite. | SQLite keeps no time zone; mixing local offsets would break newest-first ordering across DST changes. |
| 2026-11-14 | The deleted-file policy (delete the index row) stays until step 06 — confirmed by the owner. | See the entry above. |
| 2026-11-14 | Capture, engine, output and analysis settings live in `default.yaml` sections that are **required** (no defaults in code) and validated at load time. | "Config over constants" (rule 10), confirmed by the owner for the step-02 microphone timings. A missing key fails loudly instead of silently using a value nobody chose. |
| 2026-11-14 | Processing chunk = **20 ms** (`engine.chunk_ms`). | Low delay (one chunk is part of the latency) while costing almost nothing to process (RTF p95 0.06 on the laptop). |
| 2026-11-14 | Separate input and output streams joined by queues: input drops the oldest chunk when full; output prebuffers 2 chunks, drops the oldest above 8, counts underruns and re-prebuffers after one. | The two devices have independent clocks; bounded queues keep latency bounded under drift. Measured: prebuffer 2 = 0 underruns in 60 s (94 ms); prebuffer 1 = 1 underrun in 30 s (84 ms). |
| 2026-11-14 | An always-on **safety limiter** (instant attack, 50 ms release, −1 dBFS ceiling, final hard clip) on everything sent to the speakers. | The laptop mic exceeds full scale (+7.44 dB Windows gain) and the user can add +12 dB; hearing safety is not optional. |
| 2026-11-14 | **Monitoring is off by default** and the first enable requires a headphone confirmation (remembered in `localStorage`). | Laptop speakers feed back into the microphone and howl. |
| 2026-11-14 | Session recordings store the **raw input** (all channels, before the chain), in the same WAV + sidecar format as `soundspy record`. | The processed sound changes as processing improves; the raw input can always be reprocessed. One format for every recording. |
| 2026-11-14 | The `Analyzer` runs on the input chunk with sample-accurate emission schedules (rates independent of the chunk size); the mono mix for waveform/spectrogram comes from `ChannelReducer(mean)`; mel filterbank in NumPy. | Rule 4 (one place for downmixing); no torch dependency for the live pictures. |
| 2026-11-14 | Live visual frames bypass React state: they go into `liveFrames` ring buffers read by canvases in `requestAnimationFrame`; only status / recordings / toasts are in the store. Per-client WS queues drop the oldest visual messages for a slow client, never status/warning/error. | ~70 messages/s would otherwise re-render the page continuously; a background tab must not make the server hoard messages. |
| 2026-11-14 | The warning event class is `WarningEvent` (message type `warning`), not `Warning`. | `Warning` would shadow Python's built-in exception class wherever it is imported. |
| 2026-11-14 | PortAudio is re-initialised (`sd._terminate()` + `sd._initialize()`) before every session start and on `GET /api/devices`, only while no session runs; a failed open is retried once after another re-scan. | Owner's test: plugging headphones into the Realtek jack left PortAudio with stale WASAPI handles, so the next session had no output and a later one could not open the mic. Re-initialising under an open stream would kill it, hence "only while idle". The `_terminate`/`_initialize` functions are private to sounddevice but the documented way to refresh its device list. |
| 2026-11-14 | `soundspy serve` passes a uvicorn log config that also routes the `soundspy.*` loggers to the console. | Sound Spy's own warnings (output unavailable, worker errors) were invisible in the server window. |
| 2026-11-14 | Test folders have no `__init__.py`. | With them, running pytest from inside `tests/io` registered the folder as the top-level package `io`, shadowing the standard library. `--import-mode=importlib` does not need them. |
| 2026-11-15 | Large data and caches live under the D: `paths` (`D:/SoundSpyData/{external,processed,mixtures,models}`), never inside the repository; `TORCH_HOME` / `HF_HOME` / `XDG_CACHE_HOME` point to `model_cache` unless the user already set them. Code, database and own recordings stay on C:. | C: has ~31 GB free and unpacking FSD50K needs ~60 GB; both are partitions of the same NVMe SSD. The clip index stores aliased paths (`fsd50k://…`), so the data can move with a config change. |
| 2026-11-15 | Training examples are stored as **mixture recipes** (JSON lines, deterministic from the config seed) and rendered on the fly at any sample rate; no rendered mixtures on disk. | A few MB instead of ~25 GB, exactly repeatable, and the model sample rate is only chosen in step 05. |
| 2026-11-15 | Role rule with **ancestor tolerance**: a clip is foreground for a class if all its labels are inside the class's subtree or above it and at least one is inside; background if none touches any class; otherwise excluded; foreground for two classes = excluded and reported. Labels that are ancestors of another label of the same clip are ignored first. | FSD50K propagates labels to every ancestor, so parents carry no information; any other label is a real second sound that would teach a wrong target. The same-clip ancestor step handles multi-parent smearing (a car horn also carries `Alarm`) so overlaps are reported as overlaps. |
| 2026-11-15 | Foreground classes are drawn **uniformly** per mixture, then a clip of that class. | Class sizes differ by orders of magnitude; uniform drawing keeps rare classes as frequent as common ones. |
| 2026-11-15 | **No resampling cache yet**: each event's segment is read and resampled (`resample_poly`) when a recipe is rendered. | Fast enough for previews, costs no disk; a cache is worth it only once step 05 fixes the rate and training speed is measured. |
| 2026-11-15 | Events are normalised to a reference loudness (`mixtures.reference_rms_dbfs: -25`, RMS over active frames) before `gain_db`. Added to the data config. | The spec's "reference loudness" needed a value; config over constants. Measuring over active frames stops silent padding from making a clip look quiet. |
| 2026-11-15 | FSD50K split zips are extracted with 7-Zip only (found on PATH or in `C:\Program Files\7-Zip`); without it the downloader downloads everything and stops with `winget install 7zip.7zip`. Installed on the dev laptop with the owner's consent. | Python's `zipfile` cannot read multi-part archives. |
| 2026-11-15 | `classes.yaml` AudioSet names unchanged: all exist in the ontology. "traffic" keeps `Vehicle` (includes aircraft, boats, trains) pending the owner's decision. | Validation found no invalid names; narrowing the class is a meaning change for the owner to make. |
| 2026-11-15 | FSD50K: eval → test as published; the dev train/val split is made **uploader-disjoint** by moving each uploader wholly to the side holding most of its dev clips (ties → train). 2,010 of 40,966 dev clips change side; val has 2,660 clips instead of 4,170. | The proposed dev split shares 926 uploaders (57 % of val clips), which violates the no-group-in-two-splits rule; only dev/eval are uploader-disjoint. FSD50K's README allows another split if it is stated. The owner may prefer the official split (open question). |
| 2026-11-15 | Step-05 data fixes (owner): traffic = "Traffic noise, roadway noise" + "Motor vehicle (road)" (was "Vehicle"); ESC-50 classes without a match are explicitly `background` (drinking_sipping, can_opening, washing_machine) or `excluded` (engine), `null` is rejected; whole FSD50K training uploaders move to val (greedy, deterministic, logged) until every class has ≥ `splits.fsd50k.min_val_clips_per_class` = 40 val clips. | Road traffic only; cafeteria noises are useful background; ESC-50 "engine" is mostly road vehicles. 28 uploaders moved, train lost 21/23/10 chair/dishes/footsteps clips. |
| 2026-11-15 | Detector backbone **EfficientAT `mn10_as`** (MIT, 4.88 M parameters, AudioSet mAP 0.471, 32 kHz); code and front-end adapted into `detection/backbones/efficientat/` and `dsp/features.py`; weights downloaded to `model_cache` with a pinned SHA-256. | Small and fast enough for live use on the 4 GB GPU (and CPU); already knows all our classes; permissive licence, so the PANNs fallback was not needed. |
| 2026-11-15 | 1 s labelled window, a result every 0.25 s; the window is **zero-padded to 10 s** (`input_context_s`) before the model, in training and live. | Measured: the pretrained network fails on inputs < 5 s (zero-shot mAP 0.10–0.12 vs 0.41 at 5–10 s; the 4×4 last feature map is dominated by padding). | 2026-11-15 | Thresholds tuned per class on **val** (max F1); test only scored. Zero-shot baseline = max AudioSet probability over `F(c)`, thresholds also tuned on val. Fixed seeded eval windows (2 per recipe). | No decision may look at test; the same windows make runs comparable. |
| 2026-11-15 | Live inference in a separate thread with **skip-when-busy** (counted) after an EMA (α 0.5) + hysteresis (0.1) smoother; no model → session starts without the detector and warns. | The audio path never waits for the model; smoothing stops flicker; a missing model must not break listening. |
| 2026-11-15 | PyTorch datasets live in `training/datasets.py`; `soundspy.data` stays torch-free (test). | The data pipeline runs without PyTorch. |
| 2026-11-15 | torch **2.11.0+cu126** / torchaudio 2.11.0+cu126 in `backend/.venv`. | Newest torch with a matching torchaudio on a CUDA 12.x runtime (torchaudio stops at 2.11); CUDA 13 builds not used, as the owner asked. Driver found: 621.24 (newer than the 537.70 assumed). |
| 2026-11-15 | DataLoader workers on Windows get one BLAS/OpenMP thread each (`OPENBLAS/OMP/MKL_NUM_THREADS=1`, `torch.set_num_threads(1)`), validation uses half the workers, and every loader has a 120 s timeout (`training.loader_timeout_s`). | Measured: 1.67 GB committed memory and 29 threads per default worker vs 0.95 GB / 7 threads; 8 default workers exhausted the commit limit and the smoke run hung silently. |
| 2026-11-15 | The live detector warms up **on its own inference thread**; the session start waits for it (≤ 60 s). | CUDA (cuDNN/cuBLAS) initialises per thread: warmed up on the session thread, the first live window took 3.1 s and 12 windows were skipped in every GPU session. |
| 2026-11-15 | On the CPU the inference thread uses `detection.live.cpu_threads` = **1** PyTorch thread (set inside that thread only). | Measured 12/4/2/1 threads: 40/36/45/68 ms per window at 971/286/112/25 % CPU (idle threads busy-wait). 68 ms is 27 % of the 0.25 s hop; offline `detect` keeps all cores. |
| 2026-11-15 | Offline segments of one class that overlap or touch are merged. | A segment starts one window before its first active result, so a single off-frame produced overlapping segments. |
| 2026-11-15 | Extraction baseline = **detector-gated Wiener filter** (`extraction/mask_baseline.py`): a gate driven by the detector's on/off state (open 10 ms, hold 300 ms, close 200 ms, floor = `attenuation_db`) and, while open, a decision-directed Wiener gain. STFT 1024/256 at the processing rate, sqrt-Hann, latency `n_fft` samples (21.3 ms at 48 kHz) for any chunk size. | Needs no training; shows what timing information alone can do. A fixed `n_fft` delay (rather than `n_fft - hop` + whatever the chunk size leaves) keeps the output length equal to the input for every chunking. |
| 2026-11-15 | The noise estimate is the average over **detector-confirmed non-target frames** when it is fresh (≤ `noise_max_age_s`); minimum statistics is only the fallback (and the only estimate without a detector). Live, a frame counts as noise only after the target stayed inactive `noise_guard_s` (0.5 s) longer. | Measured: minimum statistics removes a *steady target* (tone −7 dB instead of +22 dB); and without the guard the detector's 0.3 s turn-on lag teaches the filter the target's onset. |
| 2026-11-15 | Empty `TargetSpec.labels` = unity gain **through the STFT** (not a bypass of it); mode changes are ramped. | Constant latency: selecting a class must not shift the sound by 21 ms. |
| 2026-11-15 | Three **activity sources** behind one interface: live `DetectionState` (causal, lagged), timeline (centred windows, zero-phase EMA + the live thresholds and hysteresis; offline) and oracle (recipe truth). The evaluation also reproduces the live lag without threads (`causal_timeline`, +0.05 s). | Separates the method's own limit (oracle) from detector errors (timeline) and lag (live). Variants of the centred decision (no smoothing, lower thresholds, erosion) were within ±0.5 dB, so the live settings were kept. |
| 2026-11-15 | Evaluation references: **IRM oracle** in the same STFT as the upper bound; besides SI-SDRi and SNRi, the median SI-SDRi, a *target missed* share and a breakdown by target duration are reported (not in the spec). | SI-SDR scores a uniformly attenuated mixture as 0 dB improvement, which hides complete misses; a few disastrous recipes dominate the mean. |
| 2026-11-15 | **Bypass** plays the chain's *dry* signal (after channel reduction) **delayed by the processing latency**; `ProcessorChain` gains `post_side` observers and `latency_samples`. | Sample-aligned A/B: switching changes only the processing. |
| 2026-11-15 | **Processing runs are files**: `outputs/processed/<run_id>.wav` + `.json` sidecar (truth); the DB indexes them. One background worker, one job at a time; `run` messages over the WS. | 2026-11-15 | **The database is a disposable index** (new rule 19): `SCHEMA_VERSION` + `meta` table; a version mismatch at start-up drops and rebuilds everything from the sidecars; `soundspy db rebuild` on demand. | 2026-11-15 | **Missing-recording policy** (revisited as planned in step 02): WAV gone + sidecar present → row kept with `missing = true`; sidecar gone too → row removed, its runs stay (own sidecars, `recording_id` NULL). | Marking keeps a recording's runs visible; but a row with no sidecar would be DB-only information that a rebuild silently loses. |
